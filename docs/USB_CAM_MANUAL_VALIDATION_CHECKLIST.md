# USB_CAM Manual Validation Checklist

> Phase 3 / Task 5
>
> 目标：为 `usb_burst_cam_4k25_manual_v1_6_3.py` 提供一份可重复执行的人工验收清单，覆盖 GUI、预览、采集、停止、输出文件与异常观察。

---

## 0. 适用范围

本清单用于以下场景：

- 本地源码运行后的人工验收
- 模块重构后的回归验收
- 打包前的手工功能确认
- 用户现场复现问题时的对照检查

**当前默认验证对象：**
- 主入口：`usb_burst_cam_4k25_manual_v1_6_3.py`
- 预期形态：Tkinter GUI 桌面工具
- 主要模式：
  - 直接连拍（direct frames）
  - 先录视频后抽帧（video then frames）

---

## 1. 验收前准备

### 1.1 环境确认

开始前确认：

- [ ] 能正常启动 Python
- [ ] `ffmpeg` 可执行文件已就绪（PATH 或程序内自动发现链路可用）
- [ ] 目标 USB 摄像头已接入并可被系统识别
- [ ] 有可写输出目录
- [ ] 当前机器具备 GUI 显示环境

- 摄像头名称：`____`
- ffmpeg 路径：`____`

## 2. GUI 启动检查

### 2.1 主程序启动

操作：

1. 启动主程序
2. 观察主窗口是否正常出现

通过标准：

- [ ] 程序能启动，不闪退
- [ ] 主窗口可见
- [ ] 关键控件存在（摄像头/模式/路径/开始停止/日志/状态区域）
- [ ] 启动时无明显 traceback
- [ ] 日志区若有初始化输出，内容可读、不刷异常

异常记录：

- 现象：`____`
- 日志/报错：`____`

### 2.2 默认状态检查

通过标准：

- [ ] 未开始采集前，“停止”按钮不可误用或行为安全
- [ ] 未开始采集前，状态文本合理（如未采集/待机）
- [ ] 图片数量、空间占用、FPS 等默认值显示合理
- [ ] 未开始采集前，不应显示残留的上一轮脏状态

---

## 3. 预览功能检查

### 3.1 启动预览

操作：

1. 选择摄像头
2. 打开预览或触发预览链路

通过标准：

- [ ] 预览能正常出现
- [ ] 画面不是全黑/卡死（允许摄像头自身短暂暖机）
- [ ] 状态区/日志区可见预览相关提示
- [ ] 预览开启后 GUI 仍可操作

### 3.2 停止预览 / 预览切换

通过标准：

- [ ] 停止预览后界面不报错
- [ ] 再次开启预览仍能工作
- [ ] 预览停止后不会残留异常状态

---

## 4. Direct 连拍模式检查

### 4.1 启动 direct 模式采集

操作：

1. 选择输出目录
2. 选择 direct frames 模式
3. 点击开始采集

通过标准：

- [ ] 点击开始后程序进入采集态
- [ ] 日志中有启动信息
- [ ] 输出目录下开始出现图片文件
- [ ] 图片数量统计会增长
- [ ] FPS / 空间估算 / 已用空间等显示合理变化
- [ ] GUI 没有明显卡顿到不可操作

### 4.2 运行中观察

至少观察 10~30 秒：

- [ ] 图片文件持续增加
- [ ] 文件名格式稳定（如 `img_000001.jpg` 递增）
- [ ] 没有间歇性 traceback
- [ ] 日志没有持续刷错误
- [ ] 停止按钮可点击

---

## 5. Video then frames 模式检查

### 5.1 启动 video_then_frames 模式

操作：

1. 切换到先录视频后抽帧模式
2. 点击开始采集

通过标准：

- [ ] 程序进入采集态
- [ ] 日志中能看出录视频流程启动
- [ ] 视频输出目录生成目标视频文件或对应中间产物
- [ ] 停止后会进入抽帧流程

### 5.2 抽帧阶段观察

通过标准：

- [ ] 抽帧完成后生成图片目录
- [ ] 图片数量大于 0
- [ ] 如果 copy 抽帧无结果，程序可自动 fallback 到 q2 路径
- [ ] fallback 后不会造成 GUI 假死
- [ ] 日志能反映主要流程变化

### 5.3 删除视频分支（若配置启用）

通过标准：

- [ ] 若启用了“抽帧后删除视频”，成功路径下视频文件被删除
- [ ] 若删除失败，程序不崩溃，日志/状态可定位问题

---

## 6. 手动停止检查

### 6.1 direct 模式手动停止

操作：

1. 开始采集
2. 运行数秒后手动点击停止

通过标准：

- [ ] 点击停止后程序能结束采集
- [ ] 不因重复点击停止而崩溃
- [ ] 停止后 UI 恢复为非采集态
- [ ] 输出文件保留完整，不出现明显损坏

### 6.2 video_then_frames 模式手动停止

通过标准：

- [ ] 点击停止后不会卡死
- [ ] 若设计允许，已录制内容仍能完成后续抽帧/整理
- [ ] 停止后 summary / metadata / csv 仍能落盘

---

## 7. 输出产物检查

每轮采集完成后，人工检查输出目录。

### 7.1 目录结构

- [ ] session 目录创建成功
- [ ] frames 目录存在（如该模式应产生图片）
- [ ] run log 存在（如设计要求）
- [ ] metadata / summary / csv 等产物存在

### 7.2 图片文件

- [ ] 图片数量与界面显示基本一致
- [ ] 随机抽查 3~5 张图片可正常打开
- [ ] 图片命名连续且格式正确
- [ ] 没有大量 0 字节损坏文件

### 7.3 `frames.csv`

- [ ] 文件存在
- [ ] header 正确
- [ ] 行数与图片数一致
- [ ] 文件名顺序正确
- [ ] `approx_time_s` / `file_size_bytes` 看起来合理

### 7.4 `summary.txt`

- [ ] 文件存在
- [ ] 包含模式、图片数量、目录、日志路径等关键字段
- [ ] 中文内容不乱码
- [ ] 可被用户直接阅读理解

### 7.5 `metadata.json`

- [ ] 文件存在
- [ ] JSON 格式合法
- [ ] 关键字段齐全
- [ ] 退出码、模式、路径、统计值与本轮行为一致

---

## 8. 路径与文件系统异常检查

建议至少抽一次非理想路径测试。

### 8.1 中文路径

- [ ] 输出目录使用中文路径时可正常运行
- [ ] `summary/csv/json` 不乱码

### 8.2 空格路径

- [ ] 输出目录包含空格时可正常运行

### 8.3 只读/不可写路径

- [ ] 指向不可写目录时程序不会静默失败
- [ ] 有明确错误提示或日志

---

## 9. 连续多轮回归检查

建议连续跑 2~3 轮。

- [ ] 第一轮结束后第二轮仍可正常启动
- [ ] 不会残留上一轮 session 状态污染下一轮
- [ ] 多轮后 GUI 没有明显越来越卡
- [ ] 多轮后路径、计数、日志显示仍正确

---

## 10. 最终验收结论

### 10.1 结果判定

- [ ] 通过：主流程与产物均符合预期
- [ ] 有条件通过：存在已知小问题，但不阻断使用
- [ ] 不通过：存在阻断级问题

### 10.2 阻断级问题定义

以下任一出现，默认不通过：

- [ ] 启动即崩溃
- [ ] 预览无法工作且无替代路径
- [ ] 无法完成一次完整采集
- [ ] 停止后卡死
- [ ] 关键输出文件缺失
- [ ] 图片全部损坏或数量明显异常
- [ ] 静默失败，用户无法知道发生了什么

## 11. 推荐执行顺序（最省事版本）

如果时间有限，最少按下面顺序执行：

1. GUI 启动检查
2. 预览检查
3. direct 模式 1 轮
4. video_then_frames 模式 1 轮
5. 手动停止检查
6. 输出产物检查（csv / summary / metadata / 图片）
7. 中文路径检查

这 7 步全过，基本就够当一次发布前人工验收。
