# USB_CAM Packaging Validation Checklist

> Phase 3 / Task 6
>
> 目标：为 `usb_cam` 打包产物（尤其是 PyInstaller 场景）提供一份分发前/分发后的验证清单，确保“能启动、能找 ffmpeg、能采集、能落盘、能报错”。

---

## 0. 适用范围

本清单用于以下场景：

- PyInstaller onefile / onedir 打包验证
- 分发给非开发机器后的首轮验收
- Windows 目标机的最小功能回归
- 发布候选版本（RC）出包前检查

**重点关注：**
- 无源码环境能否启动
- 依赖是否被正确带入
- ffmpeg 路径发现是否可靠
- 中文路径/权限/日志是否稳定
- 输出产物是否完整

---

### 1.1 打包输入确认

- [ ] 主入口正确（目标 GUI 启动脚本无误）
- [ ] 当前代码基线已验证通过
- [ ] 本地自动测试基线已记录
- [ ] 需要带入的资源文件已确认
- [ ] 需要的隐藏导入已确认

建议记录：

- Git 提交：`____`
- 打包时间：`____`
- 打包机器：`____`
- 打包方式：`onefile / onedir`
- Python 版本：`____`
- PyInstaller 版本：`____`

### 1.2 打包前最小验证

出包前至少确认：

- [ ] `pytest -q test_usb_cam_refactor.py` 通过
- [ ] 相关模块可 `py_compile`
- [ ] 主程序源码运行能正常打开 GUI

---

## 2. 打包产物结构检查

### 2.1 文件完整性

对打包输出目录/单文件做检查：

- [ ] EXE/主程序文件存在
- [ ] 文件大小看起来合理（不是明显异常的小空壳）
- [ ] onedir 模式下关键依赖目录完整
- [ ] 若随包附带 `ffmpeg.exe`，文件存在
- [ ] 若随包附带配置/说明文件，文件存在

### 2.2 安全与可读性

- [ ] 文件名清晰，不混乱
- [ ] 用户拿到包后能看懂入口文件
- [ ] 没有把临时测试垃圾一起打进去

---

## 3. 无 Python 环境启动验证

> 这是打包验证里最关键的一条。

在尽量接近真实用户环境的机器上验证。

### 3.1 冷启动

操作：

1. 将打包产物复制到目标机器/干净目录
2. 直接双击启动

通过标准：

- [ ] 无需手动安装 Python 即可启动
- [ ] 程序可正常打开 GUI
- [ ] 没有立即闪退
- [ ] 没有 DLL 缺失 / 模块缺失报错

### 3.2 首次启动日志

- [ ] 如程序有日志文件，首次启动能落盘
- [ ] 如启动失败，错误信息可定位，不是静默消失

---

## 4. ffmpeg 发现与调用验证

### 4.1 自动发现链路

按产品设计检查：

- [ ] 能从 PATH 找到 ffmpeg
- [ ] 或能从程序目录找到 ffmpeg
- [ ] 或能从既定 fallback 路径找到 ffmpeg

### 4.2 失败路径

人为制造 `ffmpeg` 缺失场景后检查：

- [ ] 程序不会静默失败
- [ ] 有明确提示 `ffmpeg` 不可用
- [ ] 错误信息用户能看懂

### 4.3 实际调用

- [ ] 预览时能成功调用 ffmpeg
- [ ] direct 模式能成功调用 ffmpeg
- [ ] video_then_frames 模式能成功调用 ffmpeg
- [ ] 停止流程不会因为 ffmpeg 子进程管理问题而卡死

---

## 5. GUI 与基础功能回归

### 5.1 GUI 基础检查

- [ ] GUI 能打开
- [ ] 基本控件可操作
- [ ] 日志区/状态区正常
- [ ] 点击按钮不会立刻报异常

### 5.2 预览功能

- [ ] 预览可打开
- [ ] 预览可停止
- [ ] 重复开关预览不崩溃

### 5.3 采集功能

至少各跑 1 轮：

- [ ] direct 连拍模式可完成一次完整采集
- [ ] video_then_frames 模式可完成一次完整采集
- [ ] 手动停止功能可用

---

## 6. 输出目录与权限验证

### 6.1 普通可写目录

- [ ] 默认输出到普通目录时可成功写文件
- [ ] session / frames / log / csv / summary / metadata 能正常生成

### 6.2 中文路径

- [ ] 输出目录含中文时能正常采集
- [ ] 生成文件名/内容不乱码

### 6.3 含空格路径

- [ ] 输出目录含空格时能正常工作

### 6.4 不可写目录

- [ ] 指向不可写目录时不静默失败
- [ ] 有明确报错或日志

## 7. 输出产物验证

每种模式至少检查一轮。

### 7.1 图片

- [ ] 图片数量 > 0
- [ ] 图片文件可正常打开
- [ ] 文件名递增规则正确
- [ ] 没有大量损坏/0字节文件

### 7.2 `frames.csv`

- [ ] 文件存在
- [ ] header 正确
- [ ] 行数与图片数匹配
- [ ] 顺序正确

### 7.3 `summary.txt`

- [ ] 文件存在
- [ ] 中文内容正常
- [ ] 关键字段存在
- [ ] 用户可直接读懂

### 7.4 `metadata.json`

- [ ] 文件存在
- [ ] JSON 合法
- [ ] 模式/路径/统计值/退出码与实际一致

---

## 8. 打包特有风险点检查

### 8.1 临时目录 / `_MEI` 问题（onefile）

- [ ] onefile 解包后运行正常
- [ ] 临时目录机制不会导致资源路径解析错误
- [ ] 若程序依赖相对路径，打包后路径仍正确

### 8.2 资源与隐藏导入

- [ ] 没有因缺少隐藏导入导致运行时崩溃
- [ ] 没有因资源文件未带入导致功能失效

### 8.3 杀软 / 系统拦截（如适用）

- [ ] 目标机器未因安全策略直接拦截运行
- [ ] 若被拦截，至少能明确定位原因

---

## 9. 多轮启动与回归稳定性

建议至少执行：

- [ ] 连续启动 3 次都正常
- [ ] 连续采集 2~3 轮无明显状态污染
- [ ] 关闭后再次打开仍能正常使用
- [ ] 多轮后日志仍可读，未出现持续异常刷屏

## 12. 推荐执行顺序（发布前最省事版本）

1. 在 Windows 机器上执行 `build.bat`
2. 确认输出目录存在：`dist\\USB_Cam_4K25\\`
3. 如采用随包 ffmpeg，放置到：`dist\\USB_Cam_4K25\\tools\\ffmpeg.exe`
4. 在尽量接近无源码/无 Python 的环境中双击启动 EXE
5. 检查 ffmpeg 自动发现
6. 跑一次预览并停止
7. 跑一次 direct 连拍
8. 跑一次 video_then_frames
9. 检查手动停止逻辑
10. 检查输出文件
11. 检查中文路径
12. 检查不可写目录报错

这 12 步都过，才能把本轮状态表述为：**Windows 打包产物已完成现场录制验收，可据此判断是否允许分发。**
